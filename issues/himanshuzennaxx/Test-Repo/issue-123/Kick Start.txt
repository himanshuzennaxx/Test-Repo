Goal
different factories provide different Excel format and use AI transform to TUU Format synchronize to 1-label system.
build an TUU Service container transform Excel to TUU Format synchronize to 1-label system.


Procedure
- Customer will regular upload their TUU Excel to media.a4appz.com , Port:8022
- DynamicLink Platform will automate download Excel file one by one and transform the Excel to JSON Format sending out to "TUU Service" API.
- TUU Service transform the source JSON to TUU Format JSON send back to DynamicLink
- DynamicLink send the transformed to https://portalpredeployadmin.1-label.com/API/TUUEdi/TuuImportApiTest.aspx

AI
- The TUU Service calls Claude through the Claude Code CLI running inside the
  container. Authenticate with CLAUDE_CODE_OAUTH_TOKEN, generated by
  `claude setup-token` - that is the supported way to run Claude Code in
  containers and CI where browser login is not available.
- Do NOT call the Anthropic Messages API with that OAuth token directly.
  The API rejects it ("OAuth authentication is currently not supported"),
  and since February 2026 Anthropic's policy prohibits subscription
  credentials for third-party services. The CLI path is the one that works.
- State clearly which environment variables you need and what each one holds.
  Do not invent credential names, and do not put any real value in
  .env.example or in any committed file.
- Concurrency matters here. Every incoming request spawning its own CLI
  process will hit the subscription rate limit. Say how you handle that -
  a queue, a worker pool, a concurrency cap, whatever you choose - and say
  what happens to a request that arrives when the limit is reached.
- Say what happens when the token expires or is revoked. The service must
  fail loudly, not silently return unconverted data.

Architecture Requirement

tuu-transform will working with claude trannsform to tuu format (sample-tuu-output.json) send back to returnUrl

Note on the source JSON
The keys in the incoming JSON differ per customer - the same field may be
"Purchase Acc No" for one and "Ref. No" for another. Do not hardcode the key
names from the example above. Say how the mapping is driven and what happens
when an unknown key appears.
